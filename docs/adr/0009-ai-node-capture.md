# ADR 0009：让 AI 抢资源点、部队占点时会停下来

- 状态：已采纳
- 日期：2026-11
- 关系：细化 ADR 0008 的资源点规则；寻路部分记录了两次失败尝试。

## 背景

ADR 0008 加了 11 个资源点，但 bench 显示**一局打完平均只有 2~3 个点被占**（最多 11）。
原因很直接：

1. 单位只会"直线奔向最近的敌方建筑"，资源点只是**路过**——占点进度刚涨一点，部队就走了。
2. AI 根本没有"去抢点"的念头，它的出兵方向永远指向敌方基地。

## 决策

### 一、占点时停下来（`holding_for_node`）

单位如果站在一个**还不属于自己的**资源点半径内，且当前没有在追敌兵，就**不移动**，就地占点。
占领完成（或被打断）后恢复行军。

这一条把"路过顺手占"变成了"停下来占"，是这次收益最大的一行改动：

```
结束时平均占领资源点: 2.9 → 6.7 / 11
```

### 二、AI 会把一半的兵派去资源点

AI 在选进攻方向时多了一步：挑一个"不是我的、离家最近"的资源点（高战略点 −500 分、敌方已占的 −300 分），
**50% 的出兵瞄准这个点**，另外 50% 还是打敌方基地。

于是部队一边推进、一边沿路占点，而不是全部扎堆去撞塔。

## 数值（300 局 AI vs AI）

```
位置: P0 21.3%  P1 22.0%  P2 25.3%  P3 21.0%   平 10.3%
对局时长 平均 122.5 秒；首次淘汰 49.6 秒；76.3% 只剩一家；超时 23.7%
联盟: 先锋 25.9% / 商会 19.6% / 教团 22.0% / 蜂群 22.3%
结束时平均占领资源点: 6.7 / 约 10
```

**意外收获**：联盟胜率被拉平了。之前先锋军团 32%、教团 19%，现在 25.9% / 22.0%。
原因应该是"部队会停下来占点"改变了节奏：打得凶不如占得稳，先锋那 25% 血量优势不再一枝独秀。

## 寻路：两次失败尝试（都回滚了）

大地图 + 有机地形下，单位靠"直线 + 墙滑行"会卡在湖湾里。试了两版改进，都更差：

| 方案 | 结果 |
|---|---|
| 全程走流场（每格中心当航点） | 超时率 40% → **98%**：为了贴格子中心走，单位绕远路 |
| "直线看得见就走直线，被挡就绕" + 0.75 秒绕路惯性 | 超时率 25% → **56%**：单位在障碍两侧来回摆 |

最终保留的是 ADR 0008 那一版：**默认直线走，完全走不动时才问流场要一个方向**。
结论：这类"目标在一个固定点、地形是静态的"场景，缺少真正的 A* 时，**任何平滑/混合策略都比"撞墙再兜底"更差**。
要做对就得真上 A* 或者"预计算到每个目标的完整路径"，那是另一个量级的工作。

## 代价

| 项 | 说明 |
|---|---|
| 部队会停在点上 | 占点期间不推进，等于给了对手喘息时间；这是有意的交换 |
| AI 只看"最近的点" | 不会为了一个高战略点长途奔袭，也不会守自己已经占下的点 |
| 点数量不稳定 | 某些种子只放下 9 个点（簇心位置被出生点挤掉），不影响玩法但截图会有差异 |

## 复审条件

1. 平均占点数 < 4 → 占点速度太慢，调 `kNodeCaptureTicks`。
2. 超时 > 30% → 部队停太久，把"占点时停下"限制为"只剩 1 个点未占"之类。
3. 联盟胜率重新拉开 8 个百分点 → 重新跑一次 A/B。
