# ADR 0004：4 人混战 + 地形

- 状态：已采纳
- 日期：2026-11
- 决策者：项目负责人
- 关系：**扩展 ADR 0003 的玩法**（1v1 三条兵线 → 4 人四角、地形决定通路），内核结构不变。

## 背景

ADR 0003 的 demo 是 1v1：1600×900、三条固定兵线、双方各 3 塔。
问题是"兵线"其实是个假概念——单位只知道往 x 轴前进，地图只是背景板。
需求是：地图大一些、加地形、支持 4 人同时对战。

## 决策

| 项 | 之前 | 现在 |
|---|---|---|
| 地图 | 1600×900 | **2400×1600** |
| 移动 | 沿 x 轴的 3 条兵线 | **2D 自由移动**，路线由地形挤出来 |
| 人数 | 2 | **4**（四角各一家：1 真人 + 3 AI） |
| 每家塔 | 3（每线一座） | **2**（沿基地→中心方向两侧） |
| 出兵范围 | 己方半场（x < 800） | **以自家基地为圆心、半径 640 的圆** |
| 地形 | 无 | **30×20 格地图**：平地/道路/森林/高地/水域/岩石 |
| 基地暴露 | 掉 1 座塔 | **掉 2 座塔（全部）** |

## 地形怎么影响玩法

| 地形 | 规则 | 为什么 |
|---|---|---|
| 水域 / 岩石 | 不可通行 | 逼出绕行路线，让"走哪条路"成为决策 |
| 森林 | 移速 ×0.70 | 穿林偷袭更慢，但能避开大路 |
| 道路 | 移速 ×1.25 | 十字大道是最快的进攻线，也是最好猜的线 |
| 高地（中央） | 站上去伤害 ×1.25，移速 ×0.85 | 中心值得争，但站上去也更容易被打 |

地图由服务端生成，四向对称（先画左上象限再镜像），保证四个角完全公平；
生成后随 `S2C_Map` 一次性下发给客户端 —— **客户端不自己算地图**，否则两份地图迟早对不上。

## 为什么不用 A*

单位移动是"朝目标直线走 + 蹭墙滑行"：直走被挡就试单轴，再不行沿垂直方向绕一步。
够用的前提是**障碍都是凸的**（湖泊、岩石都是矩形块），地图设计保证不会出现凹形陷阱。
真上 A* 要么每帧算一次（贵），要么维护路径缓存（复杂），对"20Hz、一两百个单位"来说不划算。

## 4 人局的 AI

- 目标：距离为主、残血为辅（`score = 距离 - 掉血/2 + 抖动`）。
  第一版是"永远打血最少的"，结果谁先掉血谁被三家围殴，**首次淘汰平均 23 秒**，四人局只爽二十秒。
- 防守：敌兵进入自家基地 900 像素内就回防，挡在威胁和基地之间。
- 出牌点放在"基地→目标"方向、出兵半径 85% 处，并加一点抖动，避免所有兵排队走一条线。
- 三个 AI 的卡组强度要接近：给 AI 塞攻城车/巨兽它用不明白，谁的卡组贵谁先死。

## 代价（诚实记账）

| 项 | 说明 |
|---|---|
| 视野 | 地图 3:2、窗口 16:9，所以左右有留白（深色底），不是全屏铺满 |
| 没有小地图 | 4 人局其实需要一个，但先保证能玩 |
| 首次淘汰仍然偏早 | 平均 27.6 秒；基地 3000 血 + 两塔才暴露已经是拖过一轮的结果 |
| 还没有 PvP | 4 个位置里只有 1 个真人，其余是服务端 AI |
| AI 不会绕后 | 它的落点永远在"基地→目标"的直线上 |

## 数值（200 局 AI vs AI）

```
P0 22.0%  P1 23.5%  P2 26.5%  P3 27.0%   平 1.0%
对局时长 平均 80.2 秒（最短 23.1，最长 180）
首次淘汰 平均 27.6 秒
92% 以"只剩一家"结束
```

位置胜率在 22%–27% 之间（理想 25%），说明四角地图没有明显的位置优势。

## 复审条件

1. 首次淘汰 < 20 秒 → 继续加基地血量或提高 AI 防守权重。
2. 某个位置的胜率 > 32% → 检查地图对称性或出兵半径。
3. 出现"单位卡在凹角原地抖" → 那说明地图生成了凹形障碍，先改地图，再考虑 A*。
