# ADR 0008：更大的地图、随机出生点、地图资源点

- 状态：已采纳
- 日期：2026-11
- 关系：取代 ADR 0005 的"对称阵型 + 四个降落点"；资源产出仍以 ADR 0006 的建筑为主。

## 背景

上一版的地图是 2400×1600，四个出生点是三套**中心对称阵型**里挑一套再旋转。
问题：

1. 地图太小，四家一开局就贴在一起，打起来像"四方混战的小房间"。
2. 阵型对称意味着位置完全公平 —— 但也意味着**每局的地形关系都一样**，没有"这局我从哪起飞"的感觉。
3. 地图上没有任何值得争的东西：除了对方的基地，走过去没有任何理由。

## 决策

### 一、地图放大到 2880×1920（36×24 格）

面积是原来的 1.44 倍。配套：

- 单位行军速度 +35%（`kMarchSpeedPercent`）。地图大了不提速，就变成"全程在赶路"。
- 后期产出翻倍从 120 秒提前到 **60 秒**。
- 基地血量 3300 → 2800（大地图导致超时率上升，用血量换节奏）。

### 二、地形不再镜像，改成种子生成

`Terrain(variant, seed)` 用确定性噪声生成：湖泊/河流是**带噪声边缘的团**，森林、高地、碎石零散分布，道路一横一纵、位置随机。
三张图：湖群 / 双河（带渡口）/ 火山口（中央一圈岩石）。

公平性不再靠"对称"，靠规则：

- 出生点必须可通行、周围 7×7 格≥55% 是空地；
- 四个点两两 ≥900 像素；
- 出生点周围 3 格自动清平；
- 清完再检查连通性，**不连通就直接沿直线开一条 2 格宽的路**（`ensure_connected`）。

### 三、出生点真随机

删掉 `kSpawnPatterns`，改成 `MatchConfig.spawn_seed` + `Terrain::pick_spawns`。
同一颗种子一定得到同一组出生点（可复现、可 bench），不同种子就是不同的四人站位。

### 四、地图资源点 + 高战略点

地图上散落 **11 个资源点**（3 个簇 × 3 个 + 2 个高战略点），全部避开出生点（≥380 像素）：

| 类型 | 产出 | 说明 |
|---|---|---|
| 矿脉（Materiel） | 物资 2.5/秒 | 成簇出现，像矿区 |
| 能源井（Energy） | 能源 2/秒 | 同上 |
| **高战略点（Rich）** | 物资 2.5/秒 **+** 能源 2/秒 | 只刷在离所有出生点最远的地方，是"必须派兵去拿"的点 |

**占领规则**：单位进入 240 像素半径就算在占点。人数最多的玩家每 tick 推进 1~3 点进度，
满 100 点（1 个兵约 5 秒）易主；没人时进度会慢慢退回去。**不需要新操作**——
部队路过就会占，这正好和"单位自动行军"的设定吻合。

## 数值（300 局 AI vs AI）

```
位置: P0 23.7%  P1 22.3%  P2 23.7%  P3 24.7%   平 5.7%
对局时长 平均 128.8 秒；首次淘汰 49.7 秒；75% 只剩一家；超时 25.0%
联盟: 先锋 32.1% / 商会 21.9% / 教团 19.0% / 蜂群 21.6%
```

**意外收获**：随机出生点让位置胜率从"19%~27%"收敛到"22.3%~24.7%"。
之前用对称阵型时位置差 6~8 个百分点，现在几乎抹平了 —— 说明之前的偏差来自阵型/路径的隐性不对称，
而不是玩家序号。

## 代价

| 项 | 说明 |
|---|---|
| 超时率 25% | 比 2400 地图（21%）高。大地图 = 更长的行军时间，最后两家更难决出胜负 |
| 没有寻路 | 单位是"直线 + 墙滑行"。大地图 + 有机地形下会卡在湖湾里，所以加了流场只在**卡住时**兜底 |
| 资源点收益不均衡 | 谁出生在资源点旁边谁赚；这是"随机地图"的必然代价，靠"所有点都远离出生点"缓解 |
| 新增协议字段 | 快照末尾多了 11 个资源点（每个 8 字节），一帧大约 +90 字节 |

## 复审条件

1. 超时 > 30% → 把基地血量降到 2500，或把后期翻倍提前到 45 秒。
2. 高战略点从未被占领（bench 里 `rich owned` 恒为 0）→ 说明离得太远，缩短距离或加产量。
3. 位置胜率重新拉开 8 个百分点 → 检查 `pick_spawns` 的约束是否被放得太松。
