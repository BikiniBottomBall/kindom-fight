# 《抢地》游戏设计稿 v0.1 —— 简化 RTS · 4 人混战 · 回合制

> 一句话：**3-4 名领导者争夺 5 块领地，靠发育解锁卡牌、靠卡牌运营军队，最后只有一人胜出。**
> 但它是**回合制、同时决策、无微操、无迷雾**的——这是能在 5 小时/周下做完的唯一姿势。

---

## 1. 核心循环：一个回合里到底发生什么

```
┌──────────────────────── 决策阶段（90 秒，所有人并行） ────────────────────────┐
│  每个玩家私下完成，互相看不见：                                                │
│   ① 发育：花金币建造 / 升级（每个玩家同一时间只有 1 个建造位）                │
│   ② 构筑：从牌库抽牌、买牌、弃牌（形成本回合手牌）                            │
│   ③ 军事：在己方区域招募军队、向相邻区域移动 / 发起进攻                       │
│   ④ 暗置战术卡：选 1 张手牌扣在桌上（不公开，影响本回合战斗）                 │
└──────────────────────────────────┬───────────────────────────────────────────┘
                                   ▼  全部提交 / 超时自动托管
┌──────────────────── 结算阶段（服务端一次性完成，<10ms） ──────────────────────┐
│  固定顺序结算，结果完全确定：                                                 │
│   1. 资源产出（金币、兵源）                                                    │
│   2. 建筑完工                                                                  │
│   3. 军队移动（按区域编号、玩家座位号排序）                                    │
│   4. 战斗结算（相邻区域的军队对撞 → 兵力 × 兵种克制 × 战术卡 × 骰子）        │
│   5. 占领判定、淘汰判定、胜利判定                                              │
└──────────────────────────────────┬───────────────────────────────────────────┘
                                   ▼
┌──────────────── 广播阶段（每人只收到自己那份） ───────────────────────────────┐
│  公共战报（所有人相同）+ 私有状态（只有你能看的手牌/牌库/建筑明细）           │
│  客户端把战报"播"出来：一道战报 = 一段可回放的事件序列                          │
└───────────────────────────────────────────────────────────────────────────────┘
```

**一局 8~12 回合，20 分钟以内。** 这是硬约束——超过 20 分钟，你一个人没法在 5 小时/周的节奏下反复试玩调平衡。

## 2. MVP 规则（数值待调）

### 地图
5 个区域，固定环形邻接（`1-2-3-4-5-1`，可选 1 与 3 相通）。
**不是格子，是节点 + 邻接表。** 军队在区域之间整体移动，没有单兵走位。
每块区域有产出（金币 / 兵源），占领即产出。

### 玩家
| 项 | 值 |
|---|---|
| 人数 | 2-4（不足 4 人用 AI 补位） |
| 起始 | 1 个区域、5 金币、10 张起始牌库 |
| 每回合行动点 | 2 AP（发育/构筑/军事各消耗 1 AP，重复动作消耗递增） |
| 领导者 | 4 个，各有 1 条被动 + 1 张专属卡（差异化用数据，不写代码分支） |

### 卡牌（MVP 12 张）
| 类型 | 例子 | 作用 |
|---|---|---|
| 兵种 | 长枪兵 / 盾卫 / 骑手 | 解锁可招募兵种，构成三角克制 |
| 战术 | "突袭"：本次战斗攻击 +30% | 决策阶段暗置，结算时揭晓 |
| 经济 | "集市"：本区域产出 +1 | 发展加速 |
| 阴谋 | "断粮"：目标玩家金币 -2 | 打断对手节奏 |

### 战斗结算（唯一需要"算"的地方）
```
战力 = 兵力 × 兵种克制系数(0.8 / 1.0 / 1.25) × 战术卡加成 × 掷骰(0.9~1.1, 服务端种子)
胜负 = 战力高者胜；败方军队全灭，胜方伤亡 = 败方战力 / 胜方战力 × 兵力 × 0.5
```
**战斗是一道算式，不是一场模拟。** 这是本项目最重要的成本控制点。

### 胜利条件（三选一，取最简单的组合）
- 控制 3/5 区域 → 立即胜
- 其他玩家全部淘汰 → 胜
- 第 12 回合结束 → 按「区域数 × 3 + 军队 × 2 + 金币」最高者胜

## 3. 四条红线（砍掉 RTS 成本的关键）

| ❌ 红线 | 为什么必须砍 | 砍掉后省下 |
|---|---|---|
| **没有实时 tick** | 实时 = 同步/插值/预测/补偿，是复杂度核弹 | ~80h |
| **没有单位微操** | 军队是"区域上的兵力数字 + 兵种构成"，不是一个个兵 | ~60h |
| **没有格子寻路** | 地图 = 5 节点邻接表，不是 N×M 网格 | ~40h |
| **没有战争迷雾** | 隐藏信息只有"手牌"，可见范围不做 | ~30h |

这四条不是"先不做以后加"，而是**永久不做**。想做实时 RTS 的念头一冒出来，这个项目就死了。

---

## 4. 三个关键设计决策（也是三个求职故事）

### ① 同时决策，而不是轮流行动
4 人轮流行动，一回合要等 4×60 秒 = 4 分钟，体验灾难。
改成**所有人并行提交，服务端统一结算**：
- 体验上：等待时间从 4 分钟降到 0（你决策时别人也在决策）
- 后端上：这是一次"多客户端写同一份状态"的并发问题 → 天然适合讲**快照 + 乐观并发 + 指令幂等**
- 顺带解决：卡牌游戏"暗牌同时出"的博弈感，比轮流出牌更有张力和戏剧性

### ② 结算顺序必须完全确定
按「区域编号 → 玩家座位号」固定排序，随机数一律来自服务端种子。
收益：结果可复现 → 回放、录像、反作弊、线上问题复现，四件事共用一套机制。

### ③ AI 一个模块，三处复用（最省力的设计）
| 用途 | 说明 |
|---|---|
| 单机测试对手 | 没联网时就能反复试玩调平衡（对 5h/周的你至关重要） |
| 匹配补位 | 3 人也能开局，不用等第 4 人 |
| 掉线托管 / 超时托管 | 玩家掉线或 90 秒没提交，AI 替他打完 |

写一次 AI，省三次工。这也是面试里很漂亮的工程判断：**"我用同一个 AI 模块解决了三个不同层面的问题。"**

## 5. 机制 → 后端考点 映射（这是项目值钱的真正原因）

| 玩法机制 | 对应的后端能力 |
|---|---|
| 4 人房间、同时决策 | 房间生命周期、会话管理、状态机 |
| 每人只能看到自己那份 | **状态按连接裁剪**（不能简单广播同一份字节）→ 序列化设计 |
| 指令重复提交 / 重连补提交 | 幂等、去重、序列号与 ACK |
| 掉线托管 | 心跳超时检测、状态冻结与恢复、AI 接管 |
| 确定性结算 | 随机种子、可回放事件流、服务端权威 |
| 局内经济（金币/产出） | 数值结算、防负/防溢出、审计日志 |
| 匹配补位 | 匹配算法、超时降级策略 |
| 结算阶段集中计算 | CPU 密集任务与 IO 线程隔离 |

## 6. 工时与里程碑（按 5 小时/周）

| 里程碑 | 内容 | 工时 | 累计时长 | 交付状态 |
|---|---|---|---|---|
| **M0** | 规则定稿 + 纸上推演 3 局 | 10h | 2 周 | 一页规则卡 |
| **M1** | 逻辑骨架：3 区域、12 张卡、1 种建筑、战斗算式、4 人同时结算 | 55h | 13 周 | 终端里 4 个 AI 能打完一局 |
| **M2** | 网络层：epoll Reactor + 协议 + 4 人房间 + 裁剪广播 + 断线重连 | 60h | **25 周（约 6 个月）** | ⭐ **可以开始投简历** |
| **M3** | AI 完善：托管 + 补位 + 难度档 | 25h | 30 周 | 掉线不影响对局 |
| **M4** | 内容扩充：区域 5、卡牌 20+、建筑 3、平衡调整 | 35h | 37 周 | 玩法厚度到位 |
| **M5** | MySQL 战绩 + Redis 排行 + 压测报告 + Docker | 40h | **45 周（约 10 个月）** | 完整作品 |

**关键顺序：先薄后厚。**
对求职而言，**玩法厚度不值钱，服务端骨架值钱**。所以 M1 只做 12 张卡就立刻冲向 M2 网络层，把"卡牌 20+、建筑 3 种、平衡"全部放到 M4。别在没联网的时候纠结第 15 张卡的效果。

预计总投入 ≈ 225 小时。这大概是 **10 个月**的项目。如果只想要"6 个月能讲的项目"，做到 M2 就够了。

## 7. 待定问题（需要拍板）

1. **一局 8~12 回合、20 分钟内** —— 能接受吗？（这直接决定可测试性）
2. **同时决策 + 暗置战术卡** —— 能接受吗？（这是省掉"实时"的关键）
3. **地图 5 个区域节点** —— 够不够"抢土地"的味道？
4. **2 人局也要支持吗？** 支持会多约 10h（主要是平衡和结算排序），但对测试和匹配宽容度大很多。

## 8. 下一步：纸上推演（别写代码）

用 A4 纸画 5 个圈，拿 12 张小纸条当卡牌，自己扮演 4 个玩家推演 3 局。只回答三个问题：

1. 有没有玩家会在第 3~4 回合就"无钱可花、无兵可动"，陷入空转？
2. 有没有一套"无脑早攻"的唯一最优解？（有 → 加防守优势或攻方补给成本）
3. 一局实际推了几回合、花了多久？（超过 12 回合 → 砍产出或提高胜利门槛）

推演记录直接写进 `docs/bench-paper-test.md`。**纸上跑通之前，一个字代码都不要写。**
